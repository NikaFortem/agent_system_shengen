# Шенген-аналитика: агент с инструментами (ДЗ 1)

Агент отвечает гражданам РФ на вопросы о шенгенских визах по реальным данным: сколько сейчас
рассматривают визу в конкретную страну и город, как часто отказывают, какие были похожие кейсы,
и строит визовый план к дате поездки с добавлением в календарь (после подтверждения).

Это первая часть проекта «Аналитика по шенгенским визам»: разбор русскоязычных Telegram-чатов,
метрики по странам и городам подачи, индекс сложности, база знаний, веб-приложение с дашбордом и чатом.

## Быстрый старт

```bash
pip install -r requirements.txt
python demo.py            # 6 сценариев демо (провайдер из config.yaml, по умолчанию mock)
python cli.py             # консольный чат; python cli.py --fault get_country_metrics:timeout
streamlit run app.py      # дашборд + чат с карточкой подтверждения
pytest -q                 # 28 тестов: схема, ошибки, подтверждение, таймауты, лимит шагов, адаптер GigaChat
```

Смена провайдера — только в `config.yaml` (`provider: mock | gigachat | openai`), код не меняется.
Ключи — в `.env` (см. `.env.example`), в репозиторий не попадают.

### Подключение GigaChat
1. developers.sber.ru → Studio → «Создать проект» → GigaChat API → «Настройки API» → скопировать **Authorization key**.
2. `cp .env.example .env` и вставить ключ в `GIGACHAT_AUTH_KEY=`.
3. `python scripts/check_gigachat.py` — проверит ключ, токен, список моделей и вызов функции.
4. В `config.yaml`: `provider: gigachat` (модель — `models.gigachat`, адреса API — секция `gigachat`).

## 1. Спецификация

### Пользователь и его задачи
**Кто:** гражданин РФ, который планирует поездку в Европу и выбирает, куда и когда подаваться на шенген.
Сейчас он часами читает визовые чаты, где информация разрознена и устаревает.

**Задачи:**
1. Узнать реальные сроки рассмотрения по стране и городу подачи «сейчас», а не из рекламы агентств.
2. Понять риск отказа и шанс на мультивизу.
3. Посмотреть похожие кейсы со ссылками на первоисточник.
4. Понять, когда подавать документы, чтобы успеть к поездке, и не забыть про ключевые даты.

### Инструменты (контракты, 8 полей)

| Поле | `search_visa_cases` | `get_country_metrics` | `add_visa_timeline_to_calendar` |
|---|---|---|---|
| **Имя** | search_visa_cases | get_country_metrics | add_visa_timeline_to_calendar |
| **Описание** | Реальные кейсы из @schengen_chat (#статистика). Когда: «покажи похожие истории», «были ли отказы». Не для цифр — для них get_country_metrics | Медиана/разброс срока рассмотрения по кейсам из чата + доля отказов и мультивиз по данным ЕК 2025. Когда: «сколько рассматривают», «часто ли отказывают». Цифры считает код | Рассчитать визовый план к дате вылета и добавить 4 события в календарь (.ics). Когда: «когда подавать», «добавь в календарь» |
| **Аргументы** | `country` enum ISO (IT, ES, FR…); `city` enum городов РФ или null; `outcome` approved/refused или null; `limit` 1–10 (по умолч. 5) | `country` enum; `city` enum или null; `period_days` 30–365 (по умолч. 180) | `country` enum; `city` enum или null; `trip_start` YYYY-MM-DD |
| **Что не от модели** | Источник данных, потолок выдачи (10), длина фрагмента (200 симв.) | Формулы, порог выборки (≥5 кейсов), источник ЕК | `user_id` (из сессии), «сегодня», ключ идемпотентности, путь к календарю, правила расчёта дат, факт подтверждения |
| **Результат** | `{shown, total, note: "показано 5 из 56", cases: [{posted, city, submitted, processing_days, outcome, excerpt, source}]}` | `{country, city, period_days, processing_days: {median, p25, p75, cases}, ec_2025: {applications, refusal_rate_pct, multi_entry_share_pct}, sources}` | `{status: added, file, events: [{date, title}]}` или `{status: already_exists}` или `{cancelled: true}` |
| **Ошибки** | validation, not_found, timeout, internal | validation, insufficient_data, timeout, internal | validation (дата в прошлом / > года / формат), too_late, timeout, internal |
| **Тип** | чтение | чтение | **действие** (меняет календарь пользователя) |
| **Отказ / что делать** | not_found → убрать фильтр города/решения или предложить соседнюю страну | insufficient_data → увеличить period_days до 365 или убрать город; timeout → один повтор, затем честный ответ | Без подтверждения не выполняется; too_late → подсказка со страной с самым быстрым рассмотрением |

Все ошибки возвращаются модели как обычный результат: `{"error": {"type", "message", "hint"}}`.

### Опасные действия
`add_visa_timeline_to_calendar` пишет во внешний для системы объект (календарь пользователя), а даты
основаны на статистике. Поэтому:
- **подтверждение человеком** конкретной карточки с датами; harness выполняет ровно те параметры, что были на карточке; слова модели «пользователь согласен» подтверждением не считаются;
- **пользователь берётся из сессии**, у инструмента нет поля `user_id`;
- **ключ идемпотентности** `user_id + страна + дата вылета`: повторный вызов не создаёт дублей;
- **журнал** всех вызовов и отмен в `out/audit.log`.

### Сценарии ошибок
| Сценарий | Что делает агент |
|---|---|
| Модель прислала страну не из списка / `period_days=1000` / дату `20.03.2027` | validation с понятным текстом → модель исправляет аргументы |
| Сервис метрик не ответил (таймаут) | harness сам повторяет **чтение** один раз (`read_retries`; действие не повторяется), затем модель честно говорит «данные недоступны», без выдуманных цифр |
| По стране < 5 кейсов | insufficient_data → расширить период/убрать город |
| До вылета меньше, чем медиана рассмотрения | too_late → совет перенести поездку или выбрать страну с быстрым рассмотрением |
| Модель зациклилась | лимит шагов `max_steps` |
| Модель пытается сама посчитать даты подачи | описание и системный промпт запрещают; даты считает только `add_visa_timeline_to_calendar`, при отказе от календаря план возвращается в поле `plan` |
| Исключение внутри инструмента | `internal` без стека в контексте; подробности — в журнале |

## 2. Архитектура

```
пользователь ─► cli.py / app.py (Streamlit) ─► Agent (visa_agent/agent.py): цикл ≤ max_steps
                                                 │  1. сообщения + схемы инструментов → провайдер
                                                 ▼
                     providers/: mock │ gigachat (functions) │ openai_compat (tools)
                                                 │  2. tool_call
                                                 ▼
                     tools.execute_tool: 3. JSON → 4. pydantic-схема → 5. подтверждение (действие)
                                         → 6. выполнение с таймаутом → 7. результат/ошибка в контекст
                                                 ▼
                     data.VisaStore: data/cases.json (чат) + data/ec_consulates_russia_2025.csv (ЕК)
```

- `visa_agent/tools.py` — pydantic-схемы (одна модель даёт JSON-схему для LLM и проверку для кода), реализации, `execute_tool`, подмена сбоев `FAULTS`.
- `visa_agent/providers/` — адаптеры: GigaChat (`functions` / `function_call`, роль `function`), OpenAI-совместимый (`tools` / `tool_calls`, роль `tool`), детерминированная заглушка `mock` для отладки и демо без сети.
- `visa_agent/agent.py` — цикл, лимит шагов, лимит повторов инструмента, режим подтверждения для UI (`PendingConfirmation` → `resume`).
- `app.py` — дашборд (отказы и мультивизы по ЕК, сроки по чату, таблица кейсов) и чат с карточкой подтверждения и трассой.

## 3. Данные

| Источник | Что берём | Файл |
|---|---|---|
| Telegram-чат [@schengen_chat](https://t.me/schengen_chat), 12 403 сообщения, 01.07–15.11.2026 | 137 отчётов с #статистика → 126 кейсов (страна, город, решение, дата подачи, срок рассмотрения, ссылка) | `data/cases.json` |
| [Статистика Еврокомиссии по консульствам, 2025](https://home-affairs.ec.europa.eu/policies/schengen/visa-policy/short-stay-visas-issued-schengen-countries_en) | 39 строк «страна × город» в РФ: заявления, выдано, отказы, мультивизы | `data/ec_consulates_russia_2025.csv` |

Сбор: `scripts/parse_tg_html.py` (экспорт Telegram Desktop → JSONL, **без имён авторов**),
`scripts/extract_cases.py` (правила извлечения полей). Сырые выгрузки в репозиторий не кладём.

**Ограничения:** извлечение правилами, без LLM — часть полей пустая или неточная (путаются даты поездки и решения);
отчёты чаще пишут после одобрения, поэтому долю отказов берём из ЕК; статистика ЕК за 2025 почти не отражает
запрет мультивиз с ноября 2025. Следующий шаг — LLM-разметка всех сообщений и регулярный сбор.

## 4. Демо (3 минуты)

`VISA_AGENT_PROVIDER=mock python demo.py` (или с ключом GigaChat):
1. **Обычный сценарий:** «Сколько рассматривают визу в Италию в Москве?» → `get_country_metrics` → медиана по кейсам + отказы ЕК.
2. **Действие:** «Лечу в Испанию 2027-03-20, когда подавать?» → карточка с 4 датами → подтверждение → .ics.
3. **Ошибка инструмента:** таймаут сервиса метрик → один повтор → честный ответ без выдуманных цифр.
4. **Бизнес-правило:** вылет через 25 дней в Италию → too_late + совет.

В Streamlit те же сценарии: сбой включается в сайдбаре, трасса шагов — в раскрывающемся блоке.

## 5. Чек-лист перед сдачей

| Пункт | Где |
|---|---|
| Описание каждого инструмента проходит тест стажёра (что делает, когда / когда не использовать, форматы, что возвращает) | docstring-и схем в `tools.py` |
| Аргументы проверяются по схеме, ошибка возвращается модели | `execute_tool` → `validation` с текстом; тесты `test_unknown_country…`, `test_bad_json…`, `test_bad_date_format` |
| Клиент берётся из сессии, а не от модели | `Session.user_id`; тест `test_specs_have_no_user_id` |
| Таймаут сервиса не роняет агента | `ThreadPoolExecutor` + timeout; тесты `test_real_timeout`, `test_fault_becomes_error…`, `test_agent_retries_once…` |
| Результат ограничен по размеру | `limit ≤ 10`, фрагмент ≤ 200 симв., «показано N из M»; тест `test_search_limit…` |
| Есть лимит шагов | `agent.max_steps`; тест `test_agent_step_limit` |
| Действие только после подтверждения человеком | `confirm` в `execute_tool`; тесты `test_action_needs_confirmation`, `…without_confirm_callback…`, `…exactly_confirmed_params`, `…idempotent` |
| Провайдер в конфиге, ключей нет в репозитории | `config.yaml`, `.env.example`, `.gitignore` |
| На демо видна ошибка инструмента и выход из неё | `demo.py` сценарии 4–6, `cli.py --fault`, сайдбар Streamlit |

**Известные ограничения:** адаптер GigaChat покрыт тестами без сети (`tests/test_gigachat_adapter.py`);
живое подключение проверяется `scripts/check_gigachat.py`.
